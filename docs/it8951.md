# IT8951 screens

The IT8951 driver shows images on e-paper screens with the IT8951 controller chip, as sold with Waveshare's IT8951 HAT (the board between the Raspberry Pi and the screen).

| Model (`model=`) | Size in pixels | Status |
|---|---|---|
| `"6"` | 800 × 600 | untested |
| `"7.8"` | 1872 × 1404 | untested |
| `"9.7"` | 1200 × 825 | tested |
| `"10.3"` | 1872 × 1404 | untested |

"Untested" means it should work but has not been checked on a real screen. Reports are welcome.

## Install

```bash
pip install "epdlib[it8951]"
```

This also installs `gpiod` and `spidev`, the libraries for the Raspberry Pi's pins and its SPI connection (the wired data connection to the HAT). Turn SPI on first: `sudo raspi-config`, then Interface Options, SPI.

The driver uses only GPIO 17 (reset) and GPIO 24 (busy) and SPI 0.0. Chip select stays with the kernel's SPI driver. A HiFiBerry DAC+ on the same Pi keeps its pins.

## Use

```python
from epdlib.drivers.it8951 import IT8951Driver

with IT8951Driver("9.7", vcom=-1.90) as screen:
    screen.write(image)  # full refresh
    screen.write(image2, fast=True)  # only the part that changed
    screen.sleep()
```

The `with` block wakes the screen at the start and always releases the pins and SPI at the end, even after an error.

## Settings

**`vcom`** (required): a voltage that each screen needs set for good contrast. It is printed on the screen's flat ribbon cable, for example `VCOM = -1.90V`. Use that number. A wrong value gives washed-out or too dark images. There is no default, because every screen has its own value.

**`max_refresh`** (default 4): after this many fast writes in a row, the next write is a full one. Fast writes leave faint leftovers of earlier images; a full write removes most of them. 4 is the recommended value. Higher numbers flash less often but leave more leftovers; 0 means never force a full write.

**`timeout`** (default 15 s): the longest one operation (`init`, `write`, `clear`) may take. **`ready_timeout`** (default 2 s): the longest one wait for the controller's busy line may take. When either runs out, the driver raises `DisplayTimeout`. It never waits forever.

## Refresh types

| Call | What the screen does |
|---|---|
| `write(image)` | Full refresh of the whole screen, 16 grays, with a flash (GC16, about 1 s). |
| `write(image, fast=True)` | Only the smallest rectangle that changed is sent. Black and white only: no flash (DU, about 0.4 s). With grays in that rectangle: a short flash in that rectangle only (GC16), because DU shows black and white only. Nothing changed: nothing is sent. |
| `clear()` | Long flash to white (INIT, about 2 s). Removes all leftovers, also those a full refresh leaves. Do this now and then, for example once an hour, then write the image again. |

The first write after `init()` and the first write after an error are always full, because the driver then does not know what the screen shows.

## Errors

| Error | Meaning |
|---|---|
| `ValueError` when making the driver | A setting is wrong, for example `vcom` missing. The message says which. |
| `DisplayError: no answer from the screen` | The controller sent nothing back: check the cable, the HAT and that SPI is on. |
| `DisplayError: the controller reports ...` | The screen's size does not match `model`: choose the right model. |
| `DisplayTimeout` | The screen did not finish in time. Call `close()` and `init()` to reset it. |

## Hardware test

With the screen attached:

```bash
EPDLIB_IT8951_VCOM=-1.90 uv run pytest -m hardware tests/test_it8951_hardware.py
```

It draws a test page, a few fast updates and a clear, and checks that each one finishes within its time limit.
